# 辅种查看 (CrossSeedView)

跨下载器扫描种子，按 **种子名 + 大小** 识别辅种关系，用可折叠卡片列表展示辅种数量、保存路径与明细。支持交互式筛选、批量删种、与媒体库软/硬链接的联动清理，并提供**排除（保护）名单**。

## 主要功能

- **跨下载器识别辅种**：同一时刻扫描所有已配置下载器，按 `name + size` 分组，一眼看出哪些资源做了辅种、哪些是孤种。
- **交互式筛选（可保存）**：名称/路径关键词、大小区间、辅种数量上下限、下载器筛选；筛选条件可持久化到插件配置。
- **常见目录快捷入口**：自动提取 Top 8 保存路径的公共前缀，点击 chip 一键筛选该目录。
- **明细路径操作**：详情页可复制/高亮/一键"筛选此路径"。
- **排除（保护）名单**：可配置「排除名称关键词」与「排除保存路径」，匹配的种子整组不列为可删除项，不显示删除按钮、不参与批量删除，且不会被"重置筛选"清除。
- **可选删除功能**（`allow_delete` 关闭时按钮不显示）：
  - 单行/组头三态勾选 + 批量勾选。
  - **仅删种**：只从下载器移除任务，保留文件。
  - **删种+文件+清库**：移除任务、删除源文件，并联动清理 TransferHistory 记录的媒体库软/硬链接、同刮削目录内残留的 `.nfo`/`.jpg`/字幕，清理 DownloadHistory 并发送 `DownloadFileDeleted` 事件。
- **删种通知**：可选开启，删种成功/失败均通过系统通知渠道汇总，附种子名与清理路径预览。
- **定时刷新**：默认每日 04:00 全量扫描，也可从详情页点"立即重新扫描"。

## 配置项

| 项 | 说明 |
|---|---|
| CRON | 定时刷新表达式，默认 `0 4 * * *` |
| refresh_on_init | MP 启动时是否立即扫描一次 |
| include_all_tags | 是否包含 MP 内建标签之外的全部种子 |
| min_count / max_count | 辅种数量下限/上限 |
| downloader_filter / name_keyword / path_keyword | 常用筛选缺省值 |
| size_min_gb / size_max_gb | 大小区间（GB） |
| exclude_name_keywords | **排除名称关键词**（保护用）：名称模糊匹配，不区分大小写，`\|` 分隔多个 |
| exclude_path_keywords | **排除保存路径**（保护用）：路径精确匹配，可下拉多选或手动输入 |
| allow_delete | **启用删除按钮**，默认关闭。开启后详情页出现删除按钮 |
| notify | 删种时发送通知，默认关闭 |

## 排除（保护）名单 使用说明

排除名单用于保护你不想误删的资源，例如正在做种的动漫、国产剧目录、特定保存路径下的文件。

- **生效位置**：在插件「设置」页填写 `排除名称关键词` 与/或 `排除保存路径`，保存后重载插件（或等待下次扫描）即生效。
- **匹配规则**：
  - 名称关键词：不区分大小写，支持 `\|` 分隔多个，种子名包含任一关键词即整组排除。
  - 保存路径：精确匹配，支持多选或手动输入完整路径，分组内任一保存路径命中即整组排除。
- **保护效果**：
  - 受保护的分组在详情页**不显示任何删除按钮**（单行、组头、批量入口均不可见）。
  - 即便前端绕过请求删除，后端 `_is_hash_protected` 双保险也会直接拒绝。
  - 页面顶部状态行会提示「已排除保护 N 组」。
  - 点「重置筛选」只会清空普通筛选条件，**不会清除排除名单**。
- **解除保护**：回到设置页把对应字段改空并保存即可。

## 使用注意

- **`allow_delete` 有风险**：一旦启用，明细页每一条辅种都会出现红色删除按钮。误点"删种+文件+清库"会删除源文件并清理媒体库链接，不可撤销。建议配合排除名单保护重要资源。
- **PageRender 鉴权**：详情页所有 API 都通过 `?apikey=` 参数走 apikey 分支，跟 MP 前端 axios 拦截器无关。
- **失联时的兜底策略**：媒体库软链接被外部删除后，插件仍会尝试清空刮削目录残留元数据；`TransferHistory` 三级回退（主 hash → 同组辅种 hash → content_path）覆盖辅种场景下的清理。
